## 3. 已知限制

### 3.1 产品与协作

1. **群聊多人审批策略未实现**：审批人固定为主人；群管理员、委托、法定人数是后续能力。
2. **群主转让/解散未实现**：群主不可退出或被移除；成员变更事件尚未接入撤权守卫。
3. **多分身尚未开放**：数据模型允许，产品与 UI 先按单分身落地。
4. **外部成员/机器人主体类型未开放**：当前只有 human / avatar 两类主体。

### 3.2 端侧与通知

5. **推送令牌失效不清理**：DeviceNotRegistered 只记日志，未回写清空 `pushToken`。
6. **Web/Desktop 无推送通道**：仅 WS 实时投递。
7. **端侧动作桥接未实现**：相机/文件/剪贴板等能力已上报，调用未接成工具。
8. **文件/图片上传未实现**：内容类型已注册，上传服务与对象存储未接。

### 3.3 AI 执行细节

9. **审批修改后的参数不在卡片上回显**：目前只写审计与执行。
10. **上下文预算是字符近似**，不是模型 token 精确计数。
11. **日程提醒按服务器本地时区解释**：单时区部署自洽；多时区需存时区或 UTC 时刻。
12. **auto → manual 的中途切换不会撤销本回合**：撤权守卫只能发现冻结、静默、临时档到期、接管。
13. **冻结接口跨库写入不是原子的**：先冻结核心主体、再更新 AI 侧状态，失败需补偿。
14. **legacy 审批行没有参数指纹**：允许执行并写审计告警，新审批全部强校验。

### 3.4 部署与规模

15. **多租户 / RLS / DLP / 插件市场 / 多渠道网关未实现**：单租户部署。
16. **大规模部署**：fanout 具备多节点语义，未做分片扇出；多节点需统一 `SERVER_EPOCH`。
17. **桌面端原生能力**：仅窗口容器、拖拽与图标；托盘 / 原生通知 / 自动更新未接。
18. **邮件投递**：接入 Resend；未配置 `RESEND_API_KEY` 时验证码仅打印日志（开发模式）。

## 4. 路线图

### 第一优先级（闭环与信任）

1. 推送令牌失效清理（票据回写 + 客户端重注册）。
2. 群聊多人审批 / 委托授权（对齐 design-essence §1.3）。
3. 注意力收件箱：待审批、低置信度草稿、失败例程、预算告警聚合为稳定条目，按「已修复」离场。
4. 记忆证据校验与可撤销写操作。
5. Provider 能力位与角色后备链：主模型 / 分类模型 / 审批模型各自有序降级。

### 第二优先级（能力与体验）

1. 统一外部触发信封（webhook / 邮件 / 日历）+ 幂等键 + 回执。
2. 真实工具接入（邮件、搜索、日历同步），替换演示实现。
3. 附件与多模态：上传、魔数嗅探、配额、转录只读复核。
4. 消息搜索与按设备已读位点。
5. 审批卡片回显修改后参数与指纹摘要；任务回放的人类可读视图。
6. 上下文优先级：@、回复链、未完成任务权重；提示词稳定/易变层按缓存键拆分。

### 第三优先级（规模化）

1. 多租户 / RLS / 组织策略（有明确客户信号后再做）。
2. 大群分片扇出、多区域部署。
3. 移动端正式分发（EAS）与桌面端自动更新。
